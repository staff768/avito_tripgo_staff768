# Мутационное тестирование

Проверены `internal/domain/...` и `internal/usecase/...` с помощью [go-mutesting](https://github.com/avito-tech/go-mutesting). Прогоны выполнены 6 ноября 2026 года на Go 1.27.2, darwin/arm64. Между прогонами изменены только тесты.

## Результаты

| Пакеты | Всего мутаций | Не компилируются | Поймано до → после | Выжило до → после |
|---|---:|---:|---:|---:|
| domain | 41 | 13 | 25 → 26 | 3 → 2 |
| usecase | 15 | 1 | 12 → 14 | 2 → 0 |
| **Всего** | **56** | **14** | **37 → 40** | **5 → 2** |

Из 42 компилируемых мутаций тесты сначала обнаруживали 37 (88,10%), после доработки — 40 (95,24%). Ошибок запуска и таймаутов не было.

Полные отчёты: [до](before.json) и [после](after.json). Версия инструмента, флаги и контрольные суммы исходников сохранены в [before-metadata.json](before-metadata.json) и [after-metadata.json](after-metadata.json).

Встроенный показатель `msi` учитывает некомпилируемые мутации как успешные. Здесь эти 14 случаев выделены отдельно и в число пойманных тестами не входят.

## Что показали выжившие мутации

После первого прогона выжили пять мутаций:

- **Удаление `at = at.UTC()` из `Finish`.** Тест сравнивал время через `Equal`, а этот метод проверяет момент времени без учёта часового пояса. Добавлена проверка UTC у `FinishedAt` и `UpdatedAt`. Теперь мутация обнаруживается.
- **Удаление лога `trip created` в create-usecase.** Раньше логи уходили в `io.Discard`. Теперь тест читает JSON из буфера и проверяет событие, уровень INFO и `trip_id`. Мутация обнаруживается.
- **Удаление лога `trip completed` в finish-usecase.** Добавлена такая же проверка для завершения поездки. Мутация обнаруживается. В обоих usecase также проверяется отсутствие лога об успехе при ошибке операции.
- **Удаление проверки `!math.IsNaN(lat)`.** Мутация осталась: сравнения `lat >= -90 && lat <= 90` всё равно возвращают false для NaN.
- **Удаление проверки `!math.IsNaN(lon)`.** Аналогично: NaN не проходит сравнения `lon >= -180 && lon <= 180`.

Последние две мутации эквивалентны исходному коду: для чисел явная проверка NaN и так возвращает true, а NaN отсекается границами диапазона. Результат функции не меняется, поэтому отличить эти варианты тестом нельзя. Проверки оставлены в коде, чтобы явно обозначить запрет NaN.

## Запуск

Нужны Go, Python 3 и указанная версия инструмента:

```bash
go install github.com/avito-tech/go-mutesting/cmd/go-mutesting@v0.0.0-20261002081621-9ce5f731e321
make test-mutation
```

Скрипт работает во временной копии исходников. Каждый мутант сначала компилируется, затем запускаются тесты с `-race` и таймаутом 30 секунд. Это позволяет отличать ошибку сборки от мутации, которую поймал тест.

Результат повторного запуска записывается в `latest.json`, `latest-metadata.json` и `latest.log`; сохранённые отчёты до/после не перезаписываются. Файлы `latest*` и логи исключены через `.gitignore`.

Анализатор инструмента может выводить `undefined: tripRepository`, когда разбирает файл отдельно от соседнего `contract.go`. Перед запуском тестов скрипт независимо проверяет сборку целого пакета.
